# Импорт постов MAX → черновики блога

> **Статус:** план  
> **Обновлено:** 2026-09-04  
> **Область:** только MAX (Telegram не затрагиваем)

## Цель

Автоматически подтягивать посты из MAX-канала в **черновики** блога. Публикация на сайте — только после ручной правки: заголовок, описание, текст, обложка, направление.

**Итоговая логика:** MAX даёт сырьё → сайт создаёт черновик → редактор превращает его в полноценную SEO-статью.

---

## Текущее состояние

| Аспект     | Как сейчас                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| Контент    | Astro Content Collections, `src/content/blog/*.md`                                                                         |
| Схема      | `src/content.config.ts` — `title`, `description`, `pubDate`, `heroImage`, `cardImage`, `author`, `destination`, `featured` |
| Черновики  | **Нет** — всё из коллекции считается опубликованным                                                                        |
| Выдача     | `getCollection('blog')` в `[...page].astro`, `[...slug].astro`, `JournalSection.astro`                                     |
| Публикация | Коммит `.md` + картинки → `pnpm build` → деплой                                                                            |
| MAX API    | В проекте нет клиента; есть только ссылки на канал в Footer/Contacts/Header                                                |

---

## Выбранный подход

**CLI-скрипт импорта → markdown с `draft: true` → ручная правка → снятие draft + коммит.**

По аналогии с `scripts/typograf-blog.mjs` и `scripts/optimize-images.mjs`:

- офлайн, без runtime API на сайте;
- без CMS и базы данных;
- секреты только в `.env` (паттерн как у `TELEGRAM_*`).

Альтернативы (отклонены):

- Прямое зеркало ленты на сайте — не журнал, дубли с каналом.
- Автопубликация без модерации — короткие посты MAX ≠ редакционные статьи блога.

## Этапы реализации

### Этап 1. Доступ к MAX

**Задачи владельца / заказчика:**

1. Создать или подключить MAX-бота на [dev.max.ru](https://dev.max.ru).
2. Добавить бота **администратором** в MAX-канал (права на чтение/публикацию сообщений).
3. Получить токен бота и `chat_id` канала.

**В проекте:**

- Добавить в `.env.example`:
  - `MAX_BOT_TOKEN`
  - `MAX_CHANNEL_ID`

**API (справка):**

- Базовый домен: `https://platform-api2.max.ru`
- Чтение постов: `GET /messages?chat_id={chat_id}` (бот должен быть админом канала)
- Авторизация: заголовок `Authorization: <token>`

---

### Этап 2. Схема черновиков

Расширить `src/content.config.ts`:

```ts
draft: z.boolean().default(false),
source: z.enum(['max']).optional(),
sourceId: z.string().optional(),      // ID поста в MAX
sourceUrl: z.string().url().optional(), // ссылка на пост в MAX
importedAt: z.coerce.date().optional(),
```

**Фильтрация:** везде, где читается блог, использовать:

```ts
getCollection('blog', ({ data }) => !data.draft);
```

**Файлы для правки:**

- `src/content.config.ts`
- `src/pages/blog/[...page].astro`
- `src/pages/blog/[...slug].astro`
- `src/components/JournalSection.astro`
- sitemap / `getStaticPaths` — убедиться, что draft не попадает в URL

---

### Этап 3. Скрипт импорта

**Новые файлы:**

- `scripts/import-max-blog.mjs` — основной скрипт
- `src/lib/max-api.ts` (опционально) — типы и обёртка над MAX API

**Команда в `package.json`:**

```json
"import:max-blog": "node scripts/import-max-blog.mjs"
```

**Поведение скрипта:**

1. Читает `MAX_BOT_TOKEN` и `MAX_CHANNEL_ID` из env.
2. Запрашивает последние посты канала (`GET /messages`).
3. Для каждого **нового** поста (дедуп по `sourceId` / `maxMessageId`):
   - создаёт markdown в `src/content/blog/_drafts/max-{id}.md`;
   - заполняет frontmatter с `draft: true`, `source: 'max'`;
   - сохраняет сырой текст поста в тело;
   - генерирует временный заголовок (первая строка или «Пост от {дата}»).
4. Повторный запуск **не создаёт дубли** и **не перезаписывает** уже отредактированные черновики.

**Идемпотентность:**

- Хранить список импортированных `sourceId` в frontmatter существующих файлов или в отдельном `.import-state.json` (в `.gitignore`).

---

### Этап 4. Формат черновика

**Автоматически заполняется:**

| Поле          | Источник                                   |
| ------------- | ------------------------------------------ |
| `title`       | Первая строка поста или «Пост от {дата}»   |
| `description` | Первые ~160 символов текста                |
| `pubDate`     | Дата публикации в MAX                      |
| `draft`       | `true`                                     |
| `source`      | `'max'`                                    |
| `sourceId`    | ID сообщения в MAX                         |
| `sourceUrl`   | Публичная ссылка на пост (если есть в API) |
| `importedAt`  | Дата импорта                               |
| `author`      | `'Команда ANRO TRIP'` (default)            |

**Картинки:**

- Скачивать вложения в `src/assets/blog/max/`.
- В frontmatter прописывать `heroImage` / `cardImage` при успешной загрузке.
- Если картинок нет — оставить поля пустыми; редактор добавит вручную.

**Тело поста:**

- Сырой текст/markdown из MAX — **не** готовый HTML блога.
- Редактор дорабатывает до формата существующих статей (`blog-content-*` при необходимости).

---

### Этап 5. Ручная публикация (workflow редактора)

1. Запустить `pnpm import:max-blog` (или дождаться автоматического импорта).
2. Открыть файл в `src/content/blog/_drafts/`.
3. Отредактировать:
   - заголовок и описание;
   - текст (типографика, структура);
   - `heroImage` / `cardImage` (локальные ассеты в `src/assets/blog/`);
   - `destination` (направление);
   - при необходимости `featured`.
4. Переименовать файл под нормальный slug, например `turkey-getaway.md`.
5. Перенести из `_drafts/` в `src/content/blog/`.
6. Установить `draft: false` или удалить поле `draft`.
7. Прогнать `pnpm typograf:blog` и `pnpm optimize:images`.
8. Закоммитить и задеплоить.

После деплоя статья появляется в `/blog` и в блоке «Журнал» на главной.

---

### Этап 6. Защита от случайной публикации

- [ ] Фильтр `!data.draft` во всех трёх точках выдачи блога.
- [ ] Файлы в `_drafts/` не попадают в `getStaticPaths` для `[...slug].astro`.
- [ ] Импорт не перезаписывает файлы с `draft: false`.
- [ ] Импорт не перезаписывает черновики, у которых изменён `title` или тело (опционально: флаг `edited: true`).

---

### Этап 7. Автоматизация (после ручного MVP)

**Фаза 1 (MVP):** только ручной запуск `pnpm import:max-blog`.

**Фаза 2:** расписание:

- GitHub Action по cron (например, раз в час), или
- cron на VPS.

**Рекомендация:** автосоздание PR/коммита с новыми черновиками, **без** прямой публикации на прод.

## Чеклист проверок

| Проверка               | Команда / действие                                             |
| ---------------------- | -------------------------------------------------------------- |
| Типы и Astro           | `pnpm check`                                                   |
| Сборка                 | `pnpm build`                                                   |
| Черновики не на сайте  | Открыть `/blog` — draft-статьи отсутствуют                     |
| Черновики не в Journal | Главная — блок «Журнал» без draft                              |
| Прямой URL draft       | `/blog/_drafts/...` → 404                                      |
| Публикация работает    | Снять draft → статья видна в `/blog`                           |
| Повторный импорт       | Второй запуск не дублирует файлы                               |
| Картинки               | `heroImage` / `cardImage` отображаются после `optimize:images` |
| OG / SEO               | После публикации — корректные meta и превью                    |

---

## Риски

| Риск                                    | Митигация                                                |
| --------------------------------------- | -------------------------------------------------------- |
| Случайный выход draft в прод            | Единый фильтр `!data.draft` + проверка sitemap           |
| Стиль MAX ≠ стиль блога                 | Импорт = сырьё; редактор дорабатывает вручную            |
| Картинки вне `image()`                  | Скачивание в `src/assets/blog/`, затем `optimize:images` |
| Дубли при повторном импорте             | Дедуп по `sourceId`                                      |
| Перезапись отредактированного черновика | Не трогать файлы с изменённым контентом                  |
| Секреты в репозитории                   | Только `.env`; токен не в коде и не в логах              |
| API MAX недоступен / лимиты             | Логирование ошибок; скрипт завершается с ненулевым кодом |
