# Коммерческое развитие ANRO TRIP

> **Статус:** Стратегический план  
> **Актуально на:** июль 2026  
> **Ориентир:** сначала запуск текущего сайта, затем развитие до сильного коммерческого ресурса с собственными независимыми виджетами.

---

## Главный вывод

План реалистичный, если не пытаться сразу повторить масштаб федерального туроператора. Правильная стратегия для ANRO TRIP: быстро запустить качественный продающий сайт, затем итерационно развивать его как коммерческую платформу.

Ориентир уровня `coral.ru` полезен для структуры, визуальной плотности, коммерческих блоков, направлений, фильтров и сценариев покупки. Но функциональность нужно строить модульно: контент, заявки, SEO-страницы, виджеты, интеграции, аналитика, личный кабинет.

---

## Цель проекта

Сделать из текущего сайта ANRO TRIP не просто визитку, а коммерческий ресурс для привлечения и обработки заявок:

- частные туры и пакетные направления;
- авиабилеты и отели;
- корпоративные поездки;
- подарочные сертификаты;
- подборки и акции;
- блог и SEO-страницы;
- заявки с передачей менеджерам;
- независимые виджеты поиска и подбора.

---

## Фаза 1: Довести текущий сайт до запуска

**Цель:** получить стабильный production-сайт, который можно показывать клиентам, подключать к рекламе и индексировать.

### Контент

- [ ] Обновить все тексты на главной странице.
- [ ] Проверить тексты `/cabinet`, `/terms`, `/privacy` ( `/corp` — в архиве, см. `src/_archive/corp/` ).
- [ ] Обновить фото команды, партнёров, отзывов, наград.
- [ ] Заменить временные или слабые изображения на брендовые.
- [ ] Проверить телефон, WhatsApp, Telegram, email и адрес.

### Техническая готовность

- [ ] `pnpm check` проходит без ошибок.
- [ ] `pnpm build` собирает production-версию.
- [ ] Все формы отправляют email и Telegram-уведомления.
- [ ] Все страницы открываются без 404/500.
- [ ] Мобильная версия проверена вручную.
- [ ] Деплой на Beget VPS выполнен по [deploy-prep-checklist.md](../deploy/deploy-prep-checklist.md).

### SEO минимум перед запуском

- [ ] Title/description для ключевых страниц.
- [ ] OpenGraph для главной и основных страниц.
- [ ] Sitemap и robots.txt проверены.
- [ ] Яндекс.Вебмастер и Search Console подключены после запуска.
- [ ] Метрика/аналитика подключена без лишнего клиентского JS.

## Фаза 2: Усилить коммерческую структуру

**Цель:** превратить сайт в набор продающих входных точек, а не одну длинную главную.

### Приоритетные страницы

- [ ] `/tours/turkey` — Турция.
- [ ] `/tours/egypt` — Египет.
- [ ] `/tours/uae` — ОАЭ.
- [ ] `/tours/thailand` — Таиланд.
- [ ] `/tours/maldives` — Мальдивы.
- [ ] `/business-travel` или landing командировок (вместо архивного `/corp`).
- [ ] `/gift` — подарочные сертификаты.
- [ ] `/avia` — авиабилеты.
- [ ] `/hotels` — отели.

### Коммерческие блоки на страницах

- краткое обещание ценности;
- форма заявки или быстрый CTA;
- преимущества ANRO TRIP;
- популярные сценарии поездок;
- FAQ;
- отзывы;
- связанные направления;
- условия и ограничения без мелкого шрифта.

---

## Фаза 3: Собственные независимые виджеты

**Цель:** постепенно уходить от зависимости от внешних iframe/виджетов там, где бизнесу нужна гибкость.

### Базовые виджеты

- [ ] Виджет заявки на подбор тура.
- [ ] Виджет быстрых направлений.
- [ ] Виджет подарочного сертификата.
- [ ] Виджет корпоративной заявки.
- [ ] Виджет подписки или запроса подборки.

### Поисковые виджеты

- [ ] Авиабилеты: сначала Nemo, затем оценка собственной оболочки.
- [ ] Туры/отели: сначала Tourvisor или другой партнёрский источник, затем собственный UI поверх доступного API.
- [ ] Единый стиль ANRO TRIP для всех виджетов.
- [ ] События аналитики для каждого шага поиска и заявки.

### Важное ограничение

Полноценный независимый поиск туров уровня крупного туроператора требует договоров, API, нормализации данных, цен, наличия, кеширования, ошибок поставщиков и юридической ответственности за оффер. Это отдельный продукт, поэтому его нужно делать поэтапно, начиная с заявок и оболочек над партнёрскими API.

## Фаза 4: Платформа и интеграции

**Цель:** связать сайт с операционной работой менеджеров.

- [ ] CRM или таблица заявок как единая точка обработки.
- [ ] Расширенные email/Telegram-уведомления с UTM-метками.
- [ ] Статусы заявок для менеджеров.
- [ ] Личный кабинет или переход в существующий `lk.anrotrip.ru`.
- [ ] История обращений клиента.
- [ ] Подборки туров, которые менеджер может отправлять клиенту ссылкой.
- [ ] Интеграция с аналитикой рекламы.

---

## Фаза 5: Рост и масштабирование

**Цель:** наращивать органический и платный трафик без постоянной ручной переделки сайта.

- [ ] Регулярные SEO-страницы по направлениям.
- [ ] Контент-план блога по [Контент-стратегия.md](../content/Контент-стратегия.md).
- [ ] Посадочные страницы под сезонные акции.
- [ ] A/B тесты CTA и форм.
- [ ] Улучшение Core Web Vitals.
- [ ] PWA-функции по [pwa-plan.md](./pwa-plan.md), если они дадут бизнес-эффект.
- [ ] Личный кабинет и сохранённые подборки при подтверждённой потребности.

| Горизонт     | Что реально получить                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 1–2 недели   | Запущенный сайт с обновлённым контентом, формами, базовым SEO и деплоем                                        |

| 3–6 месяцев  | Собственные виджеты заявок/подбора, первые API-интеграции, CRM-процесс                                         |
| 6–12 месяцев | Платформенный продукт с направлениями, подборками, менеджерскими инструментами и масштабируемой SEO-структурой |

---

## Риски

- Слишком ранняя попытка сделать полный аналог крупного туроператора.
- Зависимость от внешних API без договорённостей и SLA.
- Запуск без проверки форм и уведомлений.
- Много новых страниц без контентной стратегии.
- Сложные виджеты без аналитики и понимания конверсии.
- Расширение функционала до того, как текущий сайт начал приносить заявки.

---

## Практическое правило

Каждый новый этап должен отвечать на вопрос: **это увеличивает доверие, трафик, заявки или скорость обработки клиента?**

Если ответ неочевиден, задачу лучше отложить до появления данных из аналитики и реальных обращений.
