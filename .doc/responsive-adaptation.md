# Адаптив сайта ANRO TRIP

Документ описывает рабочий подход к адаптации сайта под разные устройства: телефоны, планшеты, ноутбуки и широкие десктопы.

## Можно ли сделать автоадаптив

Полностью автоматического «сделать красиво на всех устройствах» не бывает: инструменты могут показать проблемы, но финальные решения по сеткам, переносам, размерам и интерактивным зонам нужно принимать в контексте дизайна.

Для проекта ANRO TRIP оптимальный подход — системная донастройка адаптива:

- пройти все ключевые страницы по контрольным ширинам экрана;
- найти блоки, где ломаются сетки, тексты, карточки, модалки или горизонтальные скроллы;
- исправлять через существующую дизайн-систему Tailwind CSS 4 и локальные паттерны проекта;
- проверять результат в эмуляторах и, по возможности, на реальных устройствах.

## Что можно адаптировать силами агента

Агент может самостоятельно пройти сайт и доработать адаптив для:

- главной страницы;
- блога и страниц статей;
- корпоративной страницы;
- хедера и мобильного drawer;
- футера;
- карточек, секций, горизонтальных лент и каруселей;
- модальных окон и bottom sheet;
- форм и кнопок;
- изображений и декоративных элементов.

Работать нужно аккуратно: не менять замороженный `Header.astro` без явной задачи, не ломать Tailwind v4-синтаксис и не добавлять отдельные CSS-файлы.

## Контрольные размеры

Минимальный набор viewport для проверки:

| Размер    | Что проверять                               |
| --------- | ------------------------------------------- |
| `320px`   | Малые Android/iPhone SE, критичные переносы |
| `360px`   | Типовой Android                             |
| `390px`   | Современные iPhone                          |
| `430px`   | Крупные телефоны                            |
| `768px`   | Планшеты portrait                           |
| `1024px`  | Планшеты landscape / малые ноутбуки         |
| `1280px`  | Ноутбуки                                    |
| `1440px+` | Десктоп и широкие экраны                    |

Отдельно проверять вертикально низкие экраны: `height 520–680px`, потому что хедер, drawer, hero и модалки могут упираться в высоту.

## Рекомендуемый процесс

1. Запустить сайт локально через `pnpm dev`.
2. Проверить страницы по контрольным размерам.
3. Зафиксировать проблемы по блокам: хедер, hero, секции, карточки, формы, футер.
4. Вносить правки точечно через Tailwind-классы и существующие компоненты.
5. После серии правок запускать `pnpm check`.
6. Финально проверить в Chrome DevTools, Firefox и на реальных устройствах или BrowserStack.

## Чеклист адаптива

- Нет горизонтального скролла страницы, кроме специально задуманных лент.
- Текст не обрезается и не наезжает на соседние элементы.
- Кнопки и ссылки имеют удобную touch-зону.
- Модалки и bottom sheet помещаются по высоте и скроллятся внутри.
- Хедер, drawer и якорные переходы не перекрывают контент.
- Карточки сохраняют равномерные отступы и читаемую иерархию.
- Декоративные элементы не мешают чтению на малых экранах.
- Изображения используют `<Image />`, корректные размеры и не растягиваются.
- Hover-эффекты не являются обязательными для мобильного UX.
- После правок `pnpm check` проходит без ошибок.

## Когда нужен реальный девайс

Эмуляторы хорошо подходят для первичной проверки, но финально стоит смотреть реальные устройства, если менялись:

- мобильное меню;
- формы и модалки;
- горизонтальные скроллы;
- sticky/fixed-элементы;
- touch-жесты;
- блоки с `backdrop-blur`, `overflow`, `position: fixed`.

Для production-проверки помнить особенность проекта: `vite.build.cssMinify: false` в `astro.config.mjs` не менять, иначе могут сломаться blur-эффекты.
